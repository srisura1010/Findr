# Findr AI Search Validation

_Generated by `npm run validate:matching` on 2026-10-25. Raw per-query results: `test/validation/results.csv`._

## Method

- **What was tested:** the existing AI search (`/api/similar-items`) and, for selected rows, the lost-report match check (`/api/match-check`, mode `lost`). Prompts come from the same `src/lib/aiPrompts.ts` builders the live routes use, sent to Groq with the routes' settings (model `openai/gpt-oss-120b`, temperature 0, reasoning_effort low, max_tokens 1024). Responses are parsed the way the routes parse them: unparseable output counts as "no results", and ids not in the catalog are dropped.
- **Catalog:** 31 found items (catalog hash `2a0ce581d2f7`): 14 live items read from the database with the route's own filter (not claimed/returned, newest first), plus 17 test items with photos (ids 9001-9017) appended after them. 31 of 31 items share a category with at least one other item, so the right answer usually has look-alike distractors (items per category: Bags & Backpacks 3, Books & Stationery 3, Charger & Cables 3, Clothing & Accessories 3, Electronics 3, Glasses & Eyewear 3, Keys 3, Phone 3, Water Bottle 3, Headphones & Earbuds 2, Wallet & Cards 2).
- **Queries:** 52 queries (43 for items in the catalog, 9 for items that are not), labeled by type: minimal, rambler, brand, typo, misremember, absent. Queries were simulated by an AI model (ChatGPT) using five student writing-style personas (minimal, rambler, brand-only, typo, misremembers) and only the owner's memory of each item; it never saw the listings or tags. Queries for indistinguishable listings (three phone posts, two calculators for the generic 'calculator' query) accept any matching listing. One near-duplicate 'absent' query was removed because the item was in the catalog. AI-written queries may be cleaner than real student searches.
- **Scoring:** "rank" is the 1-based position of the expected item in the returned list; when a row accepts several listings, the best rank among them counts. Top-1 = the right item came first; top-3 = it was in the first three.
- **Keyword baseline (no AI):** lowercase both sides, strip punctuation, count distinct words shared between the query and each item's name + category + description + keywords; rank by that count, ties by id. No stemming or stop-word removal.
- **Model reported by Groq:** openai/gpt-oss-120b. Every response parsed as a JSON id array.

## Limits

- **Test-item tags were not made by the production vision model.** The 17 test items' `ai_keywords` were written by Claude in the production tag format. The 14 database items use real Groq tags.
- **Query source.** Queries were simulated by an AI model (ChatGPT) using five student writing-style personas (minimal, rambler, brand-only, typo, misremembers) and only the owner's memory of each item; it never saw the listings or tags. Queries for indistinguishable listings (three phone posts, two calculators for the generic 'calculator' query) accept any matching listing. One near-duplicate 'absent' query was removed because the item was in the catalog. AI-written queries may be cleaner than real student searches.
- **One small catalog** of 31 items. Results on a full school's catalog may differ.
- **One run per query.** Temperature is 0, but repeated runs are not guaranteed to return identical lists.
- **The search route only looks at the newest 200 found items**, and the match-check route only at the newest 100 (it shows the top 3). Older items are never candidates in the live app.
- **Dates and locations are not used in ranking.** The prompt contains only id, name, category, keywords and the first 80 characters of the description.
